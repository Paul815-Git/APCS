UNIT A / E

A｜建立由小到大的編號

座標很大但不同值很少時，可以將不同值排序，依序編成零、一、二。字典把原值對應到編號，便能使用短串列儲存資料。相同原值必須得到同一編號，且大小順序保持不變；壓縮不是取餘數，不能讓不同值碰巧合併。

先手算輸出，追蹤關鍵變數，再展開結果核對；能說明原因後才開始練習。

教學範例 · Python
values = sorted(set([90, -5, 90, 20]))
rank = {}
for i in range(len(values)):
    rank[values[i]] = i
print(rank[90], rank[-5])
展開範例結果
2 0

UNIT B / E

B｜編號也能還原原值

壓縮時保留排序後的不同值串列，就同時得到反查表：編號是索引，原值是該格內容。這張表不能在轉換後丟掉，因為題目最後常要求真正的座標。查詢編號超出範圍時要先處理，不可讓負索引意外還原成最後一個值。

先手算輸出，追蹤關鍵變數，再展開結果核對；能說明原因後才開始練習。

教學範例 · Python
values = sorted(set([100, 10, 100, 50]))
print(values[0])
print(values[2])
展開範例結果
10
100

UNIT C / E

C｜把次數存進短串列

壓縮後的每一格代表一種原值，不代表某一筆輸入。每讀到一次原值，就在它的編號位置加一，重複值會累積到同一格。輸出時同時走訪反查表與次數表，便能按原值排序列出分布，而不需要配置到最大座標的巨大陣列。

先手算輸出，追蹤關鍵變數，再展開結果核對；能說明原因後才開始練習。

教學範例 · Python
values = [-10, 1000]
rank = {-10: 0, 1000: 1}
count = [0, 0]
for x in [1000, -10, 1000]:
    count[rank[x]] += 1
print(*count)
展開範例結果
1 2

UNIT D / E

D｜編號差不是實際距離

壓縮只保留相對大小，不保留原本的間隔長度。原值十與一千的編號可能只差一，但距離仍是九百九十。涉及長度時必須回到原值計算。這個限制也是判斷方法是否適用的關鍵：不能拿壓縮編號直接代替幾何座標做減法。

先手算輸出，追蹤關鍵變數，再展開結果核對；能說明原因後才開始練習。

教學範例 · Python
values = [10, 1000, 1001]
print(1 - 0)
print(values[1] - values[0])
展開範例結果
1
990

UNIT E / E

E｜稀疏座標上的重量查詢

每個座標先壓縮，再把同位置的重量相加，最後建立前綴和。查詢端點不一定出現在資料內，因此不能直接查編號字典，要用下界與上界找涵蓋範圍。這把排序、合併和前綴和接在一起，每個階段都只負責一種資訊。

先手算輸出，追蹤關鍵變數，再展開結果核對；能說明原因後才開始練習。

教學範例 · Python
from bisect import bisect_left, bisect_right
positions = [10, 1000]
prefix = [0, 3, 8]
l = bisect_left(positions, 11)
r = bisect_right(positions, 1000)
print(prefix[r] - prefix[l])
展開範例結果
5
