UNIT A / E

A｜帳目依名稱累積

多筆帳目可以指向同一個人，字典用身分作鍵，累加正負金額就能得到淨額。輸出排序只決定呈現順序，不應改變加總結果。即使某人的淨額最後為零，也仍是出現過的身分；是否保留這種項目必須依題意，而不能因數值為零就刪除。

先手算輸出，追蹤關鍵變數，再展開結果核對；能說明原因後才開始練習。

教學範例 · Python
balance = {}
for name, delta in [("amy", 5), ("amy", -5)]:
    balance[name] = balance.get(name, 0) + delta
print(balance["amy"])
展開範例結果
0

UNIT B / E

B｜重複登入不能多算

在線狀態只關心每個名稱目前是否存在，適合使用集合。重複登入與重複登出在本題都忽略，不應把登入次數直接當成人數。事件依輸入順序發生，每次處理完就更新最高同時在線數；最高值記錄的是狀態大小，不是某一事件的金額或次數。

先手算輸出，追蹤關鍵變數，再展開結果核對；能說明原因後才開始練習。

教學範例 · Python
online = set()
online.add("a")
online.add("a")
print(len(online))
online.discard("b")
print(len(online))
展開範例結果
1
1

UNIT C / E

C｜同時抵達依原順序

事件時間可能沒有排序，處理前先把時間和原輸入序號一起保存。時間相同時依輸入先後處理，是明確的同分規則；序號也能讓排序後的事件仍可識別原身分。本題只重建事件順序，不混入額外模擬，讓排序鍵與輸出內容分開檢查。

先手算輸出，追蹤關鍵變數，再展開結果核對；能說明原因後才開始練習。

教學範例 · Python
events = [(3, 0, "a"), (1, 1, "b"), (3, 2, "c")]
for time, index, name in sorted(events):
    print(name)
展開範例結果
b
a
c

UNIT D / E

D｜離開與到達同時

預約以半開區間表示，結束時刻已不占用，因此同時間離開要先於到達處理。用事件的增減值作第二排序欄，負一就會排在正一之前。這項規則直接影響最高占用；用一段恰好接另一段的例子，能辨認程式是否把不重疊誤算成重疊。

先手算輸出，追蹤關鍵變數，再展開結果核對；能說明原因後才開始練習。

教學範例 · Python
events = [(2, 1), (4, -1), (4, 1), (6, -1)]
active = peak = 0
for time, delta in sorted(events):
    active += delta
    peak = max(peak, active)
print(peak)
展開範例結果
1

UNIT E / E

E｜庫存不足就整筆拒絕

更新規則必須先決定交易是否允許，再一次修改狀態。若先扣庫存再檢查不足，拒絕時忘記回復就會污染後續交易。這裡補貨一定接受，領取只有足夠時接受；紀錄拒絕次數和最終庫存，可同時檢查判斷分支以及被拒絕事件沒有副作用。

先手算輸出，追蹤關鍵變數，再展開結果核對；能說明原因後才開始練習。

教學範例 · Python
stock, demand = 3, 4
if demand <= stock:
    stock -= demand
print(stock)
展開範例結果
3
